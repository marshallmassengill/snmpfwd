
Revision 0.5.2 (unreleased)
---------------------------

Fixes:
- Add `cryptography >= 44.0.1` as a runtime dependency. pysnmp 7's
  DES and AES USM-privacy implementations import from
  `cryptography.hazmat.decrepit.ciphers` / `primitives.ciphers`
  unconditionally but only declare `cryptography` as a `[dev]`
  extra, so environments that pip-installed snmpfwd without pulling
  dev extras silently failed every SNMPv3 authPriv request with
  `decryptionError: Ciphering services not available or ciphertext
  is broken`. v2c-only deployments were unaffected. No user-visible
  API change — the fix is to make the dep explicit.

Tests:
- tests/integration/test_snmpv3.py: end-to-end SNMPv3 (USM, SHA auth
  + AES priv, authPriv) coverage. Manager and backend use DIFFERENT
  USM users and keys so a passing query proves the proxy is
  decrypting and re-encrypting across the trunk rather than passing
  wire bytes through. Also asserts that wrong-password and
  unknown-user reach `securityAuditObserver` and produce rejection
  rather than forwarding.
- tests/integration/test_resiliency.py (new): (a) trunk reconnects
  after one peer is SIGKILL'd and respawned, without restarting the
  surviving side; (b) concurrent in-flight snmpget requests each
  get their correct reply (request/response correlation correctness);
  (c) snmpget against a client pointed at a dead backend port fails
  with a clean net-snmp `Timeout` within the configured retry
  budget and the proxy processes remain responsive afterwards.


Revision 0.5.1, released 23-04-2026
-----------------------------------

Feature follow-on release on top of 0.5.0's rebuild. No wire-protocol
or runtime-dependency change; config users should note the one
client-side breaking rename.

Features:
- SIGHUP reload now also re-exec's plugin modules (in addition to the
  routing maps and classifier lists that 0.5.0 already reloaded). Each
  plugin-id block is re-exec'd from disk with the current
  plugin-options; plugin-id additions and removals in the reloaded
  config are honoured. Reload is all-or-nothing per phase — a failed
  plugin reload keeps the old plugin set in place. Trunks, credentials,
  and the plugin-modules search path still require a restart.
- Runtime counters are now reachable via SNMP, not just the periodic
  log dump. Set `SNMPFWD_METRICS_SNMP_BIND=<host>:<port>` on either
  snmpfwd-server or snmpfwd-client and an in-process read-only v2c
  agent serves the `snmpfwd.metrics` registry under the OID subtree
  exported by `snmpfwd.metrics_mib` (default root
  `1.3.6.1.4.1.55555.1.2`; a placeholder — override
  `metrics_mib.METRICS_ROOT_OID` if you have a real IANA PEN).
  Community is `public` by default, overridable with
  `SNMPFWD_METRICS_SNMP_COMMUNITY`. GET/GETNEXT/GETBULK only — no
  writes, and the agent has its own private transport-domain OID so
  it doesn't interfere with configured forwarding transports.
- `logger` plugin: the `[file] destination` option now accepts
  `${...}` macros from the request's trunk-message context. The
  first time a given resolved path is seen the plugin creates (and
  caches) a TimedRotatingFileHandler for it, letting a single proxy
  split logs per-peer / per-context / per-credential. Example:
  `destination = /var/log/snmpfwd/${snmp-peer-address}.log`. Macros
  that aren't in the context render as `_unknown` with a one-shot
  warning. Filesystem-unsafe characters in macro values are
  sanitised to `_`. Static paths with no macros behave unchanged.
- `--logging-method` is now repeatable. Each occurrence attaches an
  additional log sink, so records fan out to every configured method
  in parallel. Example: `--logging-method=stderr
  --logging-method=file:/var/log/snmpfwd/server.log:10m`. Omitting the
  flag still defaults to a single stderr sink. `log.setLogger`'s
  semantics change to match — `force=True` clears existing handlers,
  `force=False` (the new default) appends.
- systemd unit files shipped under `conf/systemd/` for snmpfwd-server
  and snmpfwd-client. DynamicUser=yes, journal-captured stderr,
  CAP_NET_BIND_SERVICE for 161/udp, `systemctl reload` wired to
  SIGHUP for the on-the-fly reload.

Cleanup:
- `endpoint.parseTransportAddress` and
  `trunking.endpoint.parseTrunkEndpoint` now share a single
  `parse_optional_port` helper. Default-port handling and error
  reporting are identical between the two parsers; both accept
  "bracketed IPv6 host without a port" (e.g. `[::1]`,
  `[fe80::1]`), which the trunk parser already tolerated and the
  SNMP-endpoint parser previously rejected. Fixed a latent bug in
  the trunk IPv6 regex that rejected any hex letter in the host
  (`[fe80::1]:30301` now parses).

Breaking config changes (client side):
- Client-config option prefix `orig-*` renamed to `server-*` for
  consistency with the internal trunk-request keys and with the
  existing `server-classification-*` group. Specifically:
  `orig-snmp-<x>-pattern` -> `server-snmp-<x>-pattern` (11 pattern
  attributes), `orig-snmp-peer-id` -> `server-snmp-entity-id`,
  `matching-orig-snmp-peer-id-list` ->
  `matching-server-snmp-entity-id-list`. No backward-compat alias;
  client configs carried forward from 0.4.x must be renamed.

CI:
- `.github/workflows/test.yml` now triggers on pushes to `rebuild`
  (the new default branch), installs `snmpsim` (the canonical
  package; `snmpsim-lextudio` drags in pysnmp-lextudio<7 which
  clobbers our pysnmp 7 runtime), explicitly installs `snmptrapd`
  (split out of `snmpd` on Ubuntu 24.04), and runs the full `tests/`
  tree rather than only `tests/integration/`.
- README shows a GitHub Actions "Tests" status badge.


Revision 0.5.0, released 23-04-2026
-----------------------------------

Major rebuild of the 0.4.5 codebase. Python 3.11+ is now the minimum;
the asyncore-based pysnmp 4.x dependency has been retired.

Platform / dependencies:
- Ported trunking from `asyncore.dispatcher` to `asyncio.Protocol` /
  `asyncio.Server`. Wire protocol unchanged (`PROTOCOL_VERSION = 3`),
  so no on-the-wire incompatibility.
- Switched to pysnmp-lextudio 7.x and pyasn1 0.6.x. Every API rename
  applied (handle_management_operation, process_pdu, send_pdu,
  release_state_information, apiPDU.get_varbinds / set_varbinds,
  rfc2576.v1_to_v2, ...). camelCase aliases that pysnmp 7 still ships
  are preserved; those it removed got explicit call-site updates.
- Dropped `pyasn1.compat.octets` (removed upstream in pyasn1 0.5+).
- Dropped UNIX-domain SNMP transport — pysnmp 7's asyncio carrier has
  no equivalent. Not used by any example config.
- Python floor raised to 3.11 to gain clean asyncio, modern type
  hints, and to align with pysnmp-lextudio's own floor. Tested on
  3.11 / 3.12 / 3.13.

Features:
- SIGHUP-triggered config reload of routing maps and classifier
  lists (bootstrap.install_reload_handler). Trunks, credentials, and
  plugin modules still require a restart. Failed reloads keep the
  previous routing untouched.
- INFORM forwarding with end-to-end confirmation. The proxy ack's
  the original INFORM sender only after the downstream has ack'd the
  proxy; on downstream failure the ack is skipped so the sender can
  retry (RFC-strict proxy semantic).
- Runtime counters with periodic log dump. Auth failures, routing
  misses, forwarded request/notification counts, INFORM ack outcomes
  (success / skipped), and trunk connection up/down are tallied and
  emitted via `runtime counters: ...` log lines. Interval is 60s by
  default, overridable via the SNMPFWD_METRICS_INTERVAL env var.
- SIGHUP is now reload (not terminate). SIGTERM/SIGINT/SIGQUIT stop
  the process via `loop.add_signal_handler` instead of the legacy
  raise-during-syscall `signal.signal` pattern, so shutdown plays
  cleanly with asyncio.

Internals:
- CLI migrated from getopt to argparse. All legacy flag names and
  short forms preserved (`-h`, `-v`, `--debug-snmp`, `--debug-asn1`,
  `--daemonize`, `--process-user`, `--process-group`, `--pid-file`,
  `--logging-method`, `--log-level`, `--config-file`).
- The ~900-line `main()` functions in snmpfwd-server and
  snmpfwd-client now delegate their shared setup (CLI + logging,
  config load, plugin manager init, transport dispatcher, trunk
  configuration, daemonize + mainloop) to `snmpfwd/bootstrap.py`.
  Script files shrank by ~100 lines each while the common paths live
  in one place.
- `snmpfwd/log.py` rewritten around stock `logging.Logger`. The
  homemade `msg = lambda x: None` sentinel and the LOG_* integer
  level constants are gone; file-sink output format preserved
  byte-for-byte.
- `snmpfwd/cli.py` new: shared ArgumentParser construction.
- `snmpfwd/metrics.py` new: counter registry + log_deltas timer.
- `snmpfwd/target_override.py` new: `lcd.get_target_address`
  monkey-patch extracted from snmpfwdclient.main() so it can be
  unit-tested.
- `snmpfwd/msgid.py` new (renamed from `snmpfwd/next.py` — the old
  name shadowed the `next()` builtin inside the package).

Fixes:
- `requestObserver` and `trunkCbFun` built regex-match keys by
  `str()`-concatenating pysnmp OctetString values. pysnmp 7
  generates engine-ids as random bytes; about 1 in 43 contains 0x0a
  or 0x0d, which stops Python's default `.` regex from matching
  `.*?#.*?`. Fix: use `prettyPrint()` for the printable hex form,
  which is stable regardless of the byte draw.
- `NotificationReceiver.process_pdu`'s "no route configured" branch
  still called `self.releaseStateInformation(...)` (Phase-1 rename
  miss). pysnmp 7 raises AttributeError, surfacing as an uncaught
  callback exception and cascading timeouts.
- `securityAuditObserver` still called
  `variables['transportAddress'].getLocalAddress()`. pysnmp 7's
  asyncio carrier delivers a plain (host, port) tuple, so the
  observer silently raised AttributeError inside pysnmp's observer
  dispatch — auth-failure log lines had been missing since the
  port.
- `CommandResponderBase.process_pdu` unconditionally calls
  `release_state_information` at return in pysnmp 7 (not the case in
  pysnmp 4.x). That broke snmpfwd's async forward-to-trunk flow.
  Fix: subclass stashes the pending state on entry and re-inserts
  before `send_pdu` from the async trunk callback.
- `UdpAsyncioTransport()` with no args creates its own fresh
  asyncio loop, separate from `AsyncioDispatcher.loop`. UDP transports
  must now be constructed as `UdpTransport(loop=dispatcher.loop)`.

Testing:
- New `tests/integration/` harness (pytest-driven) spawning net-snmp
  snmpd or snmpsim-lextudio as a backend and snmpfwd-server +
  snmpfwd-client as subprocesses connected via ephemeral trunks.
  Drives scenarios through the net-snmp CLI (snmpget, snmpgetnext,
  snmpbulkget, snmpwalk, snmpinform, snmptrap).
- New `tests/unit/` suite covering the pure-logic modules: cparser,
  trunking protocol (encode/decode round-trips for all 5 message
  types), trunking crypto (AES-CBC round-trips), endpoints, macros,
  lazylog, plugin manager, target_override, metrics.
- CI workflow across Python 3.11 / 3.12 / 3.13.

Out of scope for 0.5.0 (flagged for a later release):
- Transparent-proxy / virtual-interface integration test. Needs
  Linux iptables TPROXY + root in the test environment, which
  doesn't fit the current CI model. The code path (lcd monkey
  patch) is unit-tested via `test_target_override.py` but not
  exercised end-to-end.
- Importlib-based plugin loading (current `exec()`-based loader
  preserved to keep existing user plugins working).
